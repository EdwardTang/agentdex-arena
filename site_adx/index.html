AgentDex CLI v3

Know which model does a job better → get the job done → learn a seed.

Your model subscriptions aren't gladiators — they're a roster. AgentDex treats the pool as co-opetition: every model gets a fair shot at each job signature, results feed an append-only seed ledger, and the allocator routes the next job to whoever actually earned it — under your objective ordering, not a leaderboard's.

Built in the open: 3 independent reviewers, 22+ findings fixed pre-merge — see PR #704.

How it works

1 — prune

Constrained-Pareto selection

Candidates violating hard constraints (cost ceilings, banned models) are pruned first. Survivors are reduced to the non-dominated set, then ranked by your objective order — correctness-first and cost-first policies pick different winners from the same data.

2 — learn

Append-only seed ledger

Every run appends a seed record (signature, model, scores, timestamp) to .agentdex/seeds.jsonl. Nothing is rewritten; allocation state is always replayable. Frontier math delegates to the adx_frontier package.

3 — export

frontier.json partitions

The learned state exports as .agentdex/frontier.json: one partition per job ladder (e.g. job:bugfix) holding the non-dominated candidates with scores and receipts. Dominated candidates fall off the frontier.

Openbox: zero credential value

The backend registry never holds a secret value — only a reference.

Each backend entry carries a token_ref that is one of none, env:NAME, or file:/path. Secrets are resolved at point of use and never written into config, logs, or exports. adx openbox check probes each backend and reports an honest status:

statusmeaning
READYprobe command succeeded (e.g. the CLI is installed and answers)
UNPROBEDno probe configured for this backend yet — unknown, not assumed working
MISSINGprobe binary not found on this host
NO-AUTHprobe ran but the backend refused — credentials not in place
TIMEOUTprobe did not answer within the probe timeout

Only READY and UNPROBED appear in the evidence run above — the other three did not occur on this host.

Partial pool coverage exits non-zero on purpose: the tool refuses to pretend a roster is healthier than it is.
